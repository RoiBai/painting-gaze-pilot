# 估计轨迹（Scan path）实现与重建

轨迹只在研究结束后的研究者回看中展示。它表现 **WebGazer 库输出的视线估计样本的时间顺序**，没有识别 fixation / saccade，也不把点的大小解释成注视时长。所有圆点等大，蓝色到橙色表示该场景时间轴中的先后；数字是显示点的全局顺序号。可回放、拖动时间轴、查看完整轨迹或近期时间窗。

## 数据与分段

`src/scanpath.ts` 的 `buildScanpath()` 逐条检查保存的回调序列。只显示当前会话、当前参与者、当前画作 `free_view` 阶段、非暂停、有限坐标且在画内的有效样本。原采样数组和坐标不改写，也不额外平滑或补点。

必须先分段，再做显示抽稀。出现以下情况立即断线：

- null/无预测、画外、暂停、非 free_view 或其他会话/画作记录；
- sampleIndex 不连续、回调时间不递增，或相邻有效回调间隔超过默认 **250 ms**；
- trialId、geometryVersion 或 calibrationVersion 改变；缺少试次/几何版本时不信任连续性；
- 样本之间有显式暂停、阶段变化、重校准、几何变化等边界事件。即使一次短暂停中没有收到回调，仍不连接暂停前后的点。

这些分段规则是可视化防误连规则，250 ms 不是注视事件判据。每一条线仅表示相邻被显示样本之间的连接，不表示摄像头在两点之间测量到了直线运动。

## 显示抽稀与编号

默认 `displayIntervalMs=200`：每段保留首个真实样本，再贪心选取与上次显示点至少相隔 200 ms 的下一个真实样本，并保留该段最后一个样本。绝不生成平均坐标、插值坐标或假热点。设为 0 可显示全部原样本。

编号在完整场景序列完成抽稀后赋予，才进行时间窗筛选，因此拖动时间轴时同一显示样本编号不变。默认每 5 个显示点标一次序号，并在部分连接上显示方向箭头。numberEvery 设为 0 时隐藏数字及对应箭头，时间色标和真实样本序列仍保留。分段端点也保留，因此显示点数量不等于固定的 5 Hz；这不是固定采样率重建。

`sourceCount` 是选定时间窗内符合条件的原始回调样本数；`displayedCount` 是同窗内实际绘制的样本数。非常窄的时间窗可能有原样本但恰好没有被抽稀选中的显示点，界面会提示减小抽稀间隔。

## 时间轴

`scanpathExtent()` 以该画最早的试次开始/自由观看回调时刻为原点，以最后结束/保存回调时刻为终点。坐标时间使用已保存的父页面 `callbackTimeMs`，不是曝光时间。轴上保留暂停时间及同画重试之间的时间间隔；图头另列各段有效展示和试次墙钟累计时长。若不同试次之间有重校准，时间轴长度可能大于试次墙钟累计。

原始序列中时间倒退时断线，不排序修复或臆测真实时间。正常记录来自同页单调时钟。刷新后的会话独立标 interrupted，不能把新会话接回旧轨迹。

## 渲染与导出

`renderScanpath(session, painting, params, {fromMs, toMs, showAOI})` 接收相对时间窗；省略时间窗即绘制完整轨迹。默认轨迹参数为：

```json
{
  "width": 1000,
  "opacity": 0.85,
  "lineWidth": 1.8,
  "pointRadius": 3.5,
  "displayIntervalMs": 200,
  "maxGapMs": 250,
  "numberEvery": 5,
  "colorScale": "time-blue-orange-v1"
}
```

`width` 是导出图像区域宽度，图像区域高度依画作宽高比计算。PNG 顶部说明区 192 px，底部溯源区 100 px。完整 JSON 保存参数，可调用同一算法版本从原采样数据重建。PNG 明确列出所选时间窗、原样本/显示样本数量、段数、抽稀参数、质量状态和会话/材料版本。无有效样本时只显示原画和“无可用数据”。不生成占位轨迹。

已有会话若缺少 scanpath 字段，可以用当前默认渲染参数回看其保存的真实采样数据；这不改变其已冻结的采集配置。原图解码缓存最多保留两幅，播放时重复使用；缓存不包含摄像头视频或眼部图像。

## 验证

`tests/scanpath.test.ts` 覆盖实际样本选择、原数组不变、null/画外/暂停/非观看/跨会话分段、版本与索引断点、长间隔/时间倒退、无回调暂停事件、时间窗内计数、稳定编号、墙钟时间轴和零数据行为。测试数据只在 tests 中存在。
